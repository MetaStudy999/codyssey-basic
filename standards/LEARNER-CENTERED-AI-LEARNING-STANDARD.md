# Agent Codyssey — 학습자 중심 AI 교육·학습 체계 공통 표준 V1.0

> 승인 범위: **2026-10-26 사용자 요청에 따라 B1-1~B7-2 총 15개 미션의 기획·교육 표준 및 학습 폴더 반영**.
> 신규 미션 소스 구현·실행·배포·슬라이드 실물 제작·학습 성취 PASS는 별도 검증/승인 대상.
> 신규 Root: `training/round-04-agent/`. 기존 Round 01~03 및 루트 이력 보존.

## 1. 최종 교육 목표와 역량

학습자가 기술을 용어 수준에서 기억하는 것을 넘어 **원리 이해, 실행 예측, 코드 추적, 독립 구현, 오류 수정, 설명, 새로운 문제 응용**을 수행하도록 돕는다.

- 학습 흐름: 사전 진단 → 개념·용어 → 비유·구조도 → PRIMM 코드 학습 → 실습·오류 해결 → 자기 설명 → 평가·오답 분석 → 간격 복습 → 독립 응용.
- 평가 영역: 용어 이해, 개념 설명, 코드 예측·독해, 독립 구현, 오류 해결, 장기 기억, 새로운 문제 전이, AI 도움 수준.
- 미션 기능 PASS, 교육 콘텐츠 제작 PASS, 학습자의 MASTER/L1~L5 숙달은 **세 개의 독립 판정**.

## 2. 16가지 학습 방법

| ID | 교수학습 활동 | 확인할 실제 학습 행동 |
|---|---|---|
| M01 | 용어 카드(Flashcard) | 한글·영문·약어·정의 회상 |
| M02 | 개념 관계도(Concept Map) | 개념 차이와 연결 이유 설명 |
| M03 | 쉬운 비유·4컷 만화 | 추상 개념을 정확한 원리에 연결 |
| M04 | 왜(Why) 질문 | 기술·코드 선택의 이유 설명 |
| M05 | 비교 학습 | 유사 기술의 적용 조건과 Trade-off 비교 |
| M06 | 실행 결과 예측 | 실제 실행 전에 출력·상태 예측 |
| M07 | 코드 추적(Code Tracing) | 변수·함수·조건·데이터 변화 분석 |
| M08 | Parsons Problem | 섞인 코드의 순서와 역할 재구성 |
| M09 | 코드 빈칸 채우기 | 핵심 문법·조건·함수 직접 회상 |
| M10 | 코드 수정 실험 | 작은 수정에 따른 결과를 예측·검증 |
| M11 | Debugging | 증상→증거→원인→수정→재검증 |
| M12 | 백지 구현 | 기존 완성 코드를 보지 않고 새로 작성 |
| M13 | 자기 설명 | WHAT→WHY→HOW→VERIFY→LIMITATION |
| M14 | 문제 변형·전이 | 새로운 조건에 배운 원리 적용 |
| M15 | 간격 복습·혼합 연습 | 답을 보지 않고 일정 간격으로 회상 |
| M16 | AI 튜터·오답 처방 | 오답 원인·힌트 수준·재학습 연결 |

매 슬라이드에 16가지를 모두 강제하지 않고, **학습 목표·난이도·진단 결과에 따라 필요한 활동을 선택**한다.

## 3. 프로그래밍 학습 PRIMM

- **P — Predict:** 예제 실행 결과를 사전에 예측.
- **R — Run:** 승인된 환경에서 실제 실행, 결과 기록.
- **I — Investigate:** 변수·모듈·호출·상태·오류 추적.
- **M — Modify:** 작은 변경과 실제 차이 확인.
- **M — Make:** 빈 프로젝트에서 유사 기능 독립 구현.

입문자에게 예제·힌트를 제공하고 숙련도가 높아질수록 점진적으로 줄인다. 코드 실행 PASS만으로 원리 이해 PASS를 판정하지 않는다.

## 4. AI 튜터의 지원 정책

- **H1:** 답을 알려주지 않는 질문 / **H2:** 관련 개념 힌트 / **H3:** 문제 해결 절차 / **H4:** 요청 시 예제 해설·유사 실습.
- 평가 전후의 도움 수준·정답 공개 조건은 사용자가 통제한다. 학습 지원과 독립 수행 평가는 명확히 구별한다.
- AI는 사실을 제안할 수 있지만 **자신의 생성 정답을 자체 검토했다는 이유만으로 검증 PASS를 선언할 수 없다.** 공식 근거·독립 테스트·실제 코드·필요 시 사람의 검토로 검증한다.
- 학습 기록은 목적별 최소 수집(미션 ID·목표·오답 유형·힌트 수준·결과·시점), 비밀키·개인정보·자유 대화 원문 기본 수집 금지.

## 5. 학습 숙달 L1~L5

| 단계 | 실제 검증할 독립 역량 |
|---|---|
| L1 | 실제 코드를 보면서 원리·역할 설명 |
| L2 | 구조도만 보고 데이터·상태 흐름 재구성 |
| L3 | 자료 없이 핵심 원리·선택 이유 구술 |
| L4 | 빈 환경에서 핵심 기능 재현 |
| L5 | 새로운 문제·요구에 원리 적용 후 검증 |

지원 도구·AI 도움·힌트 사용 수준을 별도 기록. 실패를 숨기지 않고 `PASS/FAIL/NOT_VERIFIED`로 구분한다. `L5` 또는 `MASTER`는 수행 증거 없이 선언 불가.

## 6. 8개 필수 품질 게이트 QG-01~08

| Gate | 필수 점검 및 PASS 근거 |
|---|---|
| QG-01 학습 목표 연결 | 공식 Requirement ↔ 학습목표 ↔ 코드·실습 ↔ 평가 ↔ 증빙 추적 |
| QG-02 사전·사후 평가 | 동일 역량을 측정하는 동등 난이도 평가의 결과·변화 비교 |
| QG-03 AI 콘텐츠·코드 정확성 | 용어·코드·정답·힌트의 공식 근거·실행 시험·독립 검수 |
| QG-04 단계적 코드 학습 | PRIMM Predict/Run/Investigate/Modify/Make 수행 확인 |
| QG-05 개인 피드백·오답 분석 | 오답 유형→힌트→재학습→재평가 연결 |
| QG-06 독립 구현·재현 | AI 도움 수준을 기록하고 L1~L5 별도 수행 평가 |
| QG-07 접근성·학습부담 | 가독성·대체 텍스트·자막·키보드·난이도·사용성 검사 |
| QG-08 개인정보·실습 보안 | 최소 수집·비밀정보 제거·실습 실행 범위·권한 통제 |

각 게이트는 **`NOT_VERIFIED`가 기본값**. 계획 또는 파일 존재만으로 실제 교육·검증 PASS가 아니다.

## 7. 4종 슬라이드 + 학습 활동 자료

승인된 발표 16장, 학습 45장, 기술 부록 15~25장, 복습 1~2장 및 `05-assets/` 유지. 별도 `08-presentation/06-learning-activities/` 아래 `glossary/`, `concept-maps/`, `code-tracing/`, `coding-labs/`, `debugging/`, `question-bank/`, `review/`로 **학습 자료 기획 영역**을 분리한다.

학습용 45장은 목표/사전평가(01~04), 용어/비유(05~10), 원리/설계(11~16), 실제 코드/PRIMM(17~24), 주요 기능(25~30), 안전/예외(31~34), 실제 실행(35~38), 오류/독립 재현(39~42), 복습/평가(43~45). 미션 B1~B7 기술 분야에 따라 실제 내용을 치환한다.

- 한 용어: 한글명(English Full Name, 약어)·정의·왜 필요한가·관련 개념·실제 적용·검증 질문.
- 어려운 기술: ① 친숙한 비유/4컷 만화 → ② 기술 구조도 → ③ 실제 신규 코드 → ④ 실제 실행/테스트.
- 코드는 실제 경로/SHA로 역추적; AI 생성 설명 이미지 `AI-VISUAL/MOCKUP`과 `CODE/RUNTIME/EVIDENCE` 구분.
- 편집 가능한 PPTX/PDF, 화면별 가독성·접근성·동일 내용 검사. 기존 Round의 그림·증빙을 신규 수행 결과로 오인 금지.

## 8. 복습·적응형 평가

초기 복습 운영안: **학습 직후 → 1일 → 3일 → 7일 → 14일 → 30일**. 고정된 최적 간격이 아니라, 성취도·오답·문제 난도에 따라 조정할 수 있는 출발점이다.

사전·사후 평가는 동일 역량·동등 난도 문제를 사용하며 개념 회상, 코드 추적, 직접 수행, 전이 과제를 포함. 학습 기록의 정확성·동의·보관기한·접근권한은 실제 기능 개발에 앞서 정의한다. 단일 객관식 점수만으로 숙달 선언 금지.

## 9. 고정 00~09 개발 목차와 연계

| 단계 | 학습 체계 업무 |
|---|---|
| 00 | 교육 목표·16개 기법·8개 게이트·4종 패키지 계획 확정 |

| 04 | 별도 승인 이후 신규 코드와 실제 실습 예제 구현 |
| 05 | 코드·AI 설명·정답·힌트·접근성·보안 검증 |

## 10. 완료 판정

미션 기능 완료, 4종 학습자료 제작, 학습자 숙달은 각기 다른 축. 실제 요구→구현→실행→검증→증빙·평가까지 모두 확인한 경우에만 각 축의 PASS/CLEAR 후보이다. 공식 평가자의 판정은 내부 계획서의 판정과 분리한다.

## 2. 학습용 45장 공통 단원

1. 01~04 **미션 이해 / 학습 지도** — 목표·문제·전체 구조
2. 05~10 **첫 번째 핵심 기술** — 입문 개념·원리·용어·간단한 실습
3. 11~16 **두 번째 핵심 기술 / 설계** — 구성요소·자료구조·레이아웃·도식
4. 17~24 **실제 코드 / 상태 / 동작** — 모듈·함수·데이터 흐름·원리 추적
5. 25~30 **인터페이스 / 연동 / 비동기 또는 핵심 알고리즘** — 정상·오류 경로
6. 31~34 **안전성 / 접근성 / 예외처리** — 미션에 해당하는 요구만 적용
7. 35~38 **실행 / 시험 / 검증** — 실제 작업의 검증 가능한 증빙
8. 39~42 **문제해결 / 재현 / 기술 결정** — 오류 원인·대안·개선 전후
9. 43~45 **복습 / 공식 평가 / 자기 설명** — 10초·30초·1분 구술, 학습 숙달 별도 평가

위 단원은 공통 **교수학습 구조**이며 특정 언어/웹 기능을 B2~B7에 무조건 강제하지 않습니다. 미션별 주요 개념으로 바꾸어 사용합니다.

## 4. 한 개 개념의 학습 슬라이드 규칙

핵심 용어 = **한글명(English Full Name, 약어)** + 한 줄 정의 + 왜 필요한가 + 언제 쓰는가 + 공식 요구사항 + 현재 미션 실제 코드 위치 + 예상 오류/반례.

어려운 개념을 1~3개 선정하여 **① 쉬운 비유/4컷 만화 → ② 정확한 기술 구조도 → ③ 실제 소스 코드 → ④ 직접 실행·검증**으로 연결합니다. 설명용 생성 화면에는 `AI-VISUAL` 또는 `MOCKUP`을 표시하고, 실행 결과처럼 표현하지 않습니다. 실제 검증 화면은 `RUNTIME` 또는 `EVIDENCE`이며 코드 경로·버전(SHA)·실행 일시·결과와 연결합니다.

## 5. 학습·숙달 게이트

- **L1:** 실제 코드를 보면서 기능과 원리를 설명
- **L2:** 코드 없이 구조도만 보고 처리 흐름 설명
- **L3:** 자료 없이 자신의 말로 핵심 기술 설명
- **L4:** 빈 환경에서 핵심 기능 재현
- **L5:** 유사한 새로운 문제에 원리 적용

미션 기능 시험의 `PASS`와 학습 숙달 `MASTER`는 구분합니다. 실제 증빙 없으면 `NOT_VERIFIED`, 독립 품질 게이트 충족 전 `DRAFT`입니다.

## 6. 작성 시기 및 도구

- **00 계획:** 4종 패키지 목표·범위·순서 승인 기록.
- **01 요구사항:** 공식 PDF/평가 문항과 슬라이드 학습목표 연결.
- **02 분석:** 이전 자료는 학습 참고 전용; 새 Round 구현·실행의 사실로 복사 금지.
- **03 설계:** 슬라이드 목차·핵심 개념·4컷 만화·도식 스토리보드 초안.
- **04 구현:** 실제 새 코드를 작성하며 코드 추적 위치를 수집.
- **05~07 검증·평가:** 실제 기능, API/CLI/DB, 실패 사례, 증빙 및 자기 설명을 확보.
- **08 발표:** 4종 패키지의 PPTX/PDF 제작, 실제 증빙 치환, 개별 화면 검수.
- **09 인계:** 원본·수정본·PPTX/PDF·발표 대본·출처·평가 결과 버전 보존.

권장 자료는 **편집 가능한 PPTX**, PDF 및 실제 자료 출처 맵. 반드시 실제 자료로 재검증합니다. 기존 Round 02 발표 표준 및 V3 덱은 참고만 하며 새 Round 04 PASS로 승격하지 않습니다.

## 7. 완료 기준

각 자료의 **내용 정확도 / 출처 및 실제 증빙 무결성 / 평가 요구 매핑 / 가독성 / 학습 가치 / 재현성 / 접근성 / PPTX↔PDF 일치** 확인. 장수만 채웠다는 사실로 `FINAL` 또는 `GOLDEN MASTER`를 선언하지 않습니다.

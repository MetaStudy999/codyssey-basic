## 3. Mission-derived Scope

- FastAPI `Depends`를 이용해 인증 로직을 구현한다.
- 인증 방식은 Source가 허용하는 session 또는 JWT 중 하나를 선택하고 이유를 설명한다.
- 로그인 성공/실패가 명확하고 logout이 동작해야 한다.
- 공개 route와 보호 route를 구분하고 비로그인 사용자의 핵심 기능 접근을 차단한다.
- 로그인 상태에 따라 UI가 달라져야 한다.
- SQLAlchemy ORM model 최소 3개를 두고 최소 2개 이상의 1:N 또는 N:1 관계를 구성한다.
- 최소 1개 양방향 관계를 `relationship + back_populates`로 구현한다.
- 관계 데이터를 화면에서 함께 출력한다.
- 부모 삭제 시 자식 처리 정책을 business 의미에 맞게 선택하고 이유를 남긴다.
- 단순 CRUD를 넘어 상태가 변경되는 핵심 business function 최소 1개를 구현한다.
- 상태 변경 전/후가 화면 또는 응답에서 명확히 확인되어야 한다.
- 핵심 데이터는 SQLAlchemy ORM + SQLite/PostgreSQL에 저장한다.
- Jinja2 SSR에서 로그인 → 핵심 기능 → 생성/조회 → 상태 변경 → 결과 확인 흐름이 이어져야 한다.
- `auth/`, `routers/`, `services/`, `repositories/`, `models/`, `templates/` 역할을 분리한다.

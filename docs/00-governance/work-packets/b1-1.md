## 3. Mission-derived Scope

현재 제공된 Mission PDF 기준 사전 수행범위다. G1에서 재검증한다.

- SSH 포트를 `20022`로 변경하고 root 원격 로그인을 차단한다.
- UFW 또는 firewalld를 활성화하고 인바운드 TCP `20022`, `15034`만 허용한다.
- `agent-admin`, `agent-dev`, `agent-test` 계정과 `agent-common`, `agent-core` 그룹을 구성한다.
- `$AGENT_HOME/upload_files`, `$AGENT_HOME/api_keys`, `/var/log/agent-app`의 소유권/권한/ACL을 최소 권한으로 구성한다.
- `AGENT_HOME`, `AGENT_PORT=15034`, upload/key/log 관련 환경변수와 키 파일을 준비한다.
- 제공 앱을 일반 계정으로 실행하고 Boot Sequence 5단계 `[OK]`, `Agent READY`, `0.0.0.0:15034 LISTEN`을 확인한다.
- `$AGENT_HOME/bin/monitor.sh`를 구현한다.
- monitor는 프로세스와 포트 실패 시 `exit 1`, 방화벽 비활성은 WARNING으로 처리한다.
- CPU/MEM/DISK 사용률을 수집하고 Mission 임계값에 따라 WARNING을 출력한다.
- `/var/log/agent-app/monitor.log`에 타임스탬프/PID/CPU/MEM/DISK_USED를 누적 기록한다.
- 로그 크기 관리 정책으로 최대 10MB/10개 수준을 유지한다.
- `agent-admin` crontab에서 `monitor.sh`를 매분 실행하고 자동 로그 증가를 검증한다.

## 6. G3 TEST

최소 검증 후보:

- `sshd` 설정 및 `ss -tulnp`로 SSH 20022 확인
- root SSH 차단 확인
- 방화벽 활성/허용 포트 확인
- `id`, `ls -l`, `getfacl` 등으로 계정/그룹/권한 확인
- 앱 Boot Sequence와 15034 LISTEN 확인
- monitor 프로세스/포트 정상 및 실패 케이스
- CPU/MEM/DISK 파싱 결과와 WARNING 조건
- 로그 한 줄 포맷과 누적 기록
- cron 등록 후 실제 1~2분 경과 로그 증가
- 로그 보존/회전 동작

실제 OS 설정과 cron 시간 경과가 필요한 검증은 AI가 수행할 수 없는 환경이면 `NEEDS-RUNTIME`으로 둔다.

- [ ] Requirement 누락 여부

- [ ] 로그 경로/권한/보존 정책 일치 여부

기본 Reviewer 1개만 사용하고, 추가 검토는 명확한 Trigger가 있을 때만 사용한다.

## 8. G5 RUNTIME / G6 EVIDENCE

필수 Evidence 후보:

- SSH `20022` 및 root 원격 로그인 차단
- 방화벽 활성 및 `20022/tcp`, `15034/tcp` 허용
- 계정/그룹 생성 결과
- 디렉터리 권한/ACL
- Boot Sequence 5단계와 `Agent READY`
- `monitor.sh` 실행 결과
- `monitor.log` 최근 누적 라인
- crontab 등록 및 자동 실행 후 로그 증가

Evidence는 실제 명령 출력/로그/스크린샷을 사용하고 예상 출력으로 대체하지 않는다.

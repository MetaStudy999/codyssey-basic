## 3. Mission-derived Scope

- 회원가입, 로그인, 로그아웃을 구현하고 비밀번호를 hash 저장한다.
- 로그인 성공 시 JWT 등 Source가 허용하는 인증 토큰/상태를 사용한다.
- 비로그인 사용자는 AI chatbot과 board의 보호 기능에 접근할 수 없다.
- 인증 전/후 UI가 구분된다.
- B7-1 chatbot을 사용자별로 분리한다.
- 각 사용자는 자신의 conversation session만 조회할 수 있다.
- conversation session 생성/목록/메시지 조회/메시지 전송/AI response 생성이 동작한다.
- 다른 user session 접근은 403 또는 404 등 적절한 error로 차단한다.
- Board는 list/detail/create/update/delete를 지원한다.
- 전체 사용자는 list/detail을 볼 수 있고, create는 로그인 사용자, update/delete는 작성자만 허용한다.
- post는 최소 title/content/author/created_at을 포함한다.
- backend 기능은 RESTful API로 제공하고 front-end는 해당 API를 통해 통신한다.
- URL, HTTP method, status code가 REST 원칙에 맞아야 한다.
- 외부 cloud URL에서 signup → AI chat → board 전체 흐름이 동작한다.
- 기술 문서에 ERD, API specification, system architecture diagram을 포함한다.
- Mission/Evaluation에서 협업 flow를 요구하면 feature → develop → main PR 추적을 실제 GitHub Evidence로 남긴다.

## 5. G2 BUILD

- [ ] B7-1의 안정된 기능을 불필요하게 다시 작성하지 않고 incremental enhancement를 우선한다.
- [ ] user identity와 모든 owned resource에 명시적 FK/ownership relation을 둔다.
- [ ] authorization은 front-end 버튼 숨김이 아니라 backend에서 강제한다.
- [ ] route/API status code contract를 먼저 정의하고 front-end와 맞춘다.
- [ ] password/token/API key는 안전하게 관리하고 log에 노출하지 않는다.
- [ ] B7-1 schema migration이 필요하면 데이터 손실 방지 계획을 먼저 만든다.

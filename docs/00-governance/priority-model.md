# Priority Model

Growth Stage와 수행 중요도를 분리한다.

## REQUIRED

현재 목표, 공식 Mission, 평가, 필수 운영을 위해 반드시 수행해야 한다.

예:
- 공식 필수 Mission
- 평가 통과에 필요한 구현/테스트/Evidence
- 보안상 반드시 필요한 Secret 관리

## RECOMMENDED

현재 성장 목표와 강하게 연결되어 있으며 수행 가치가 높다. 다만 미완료가 즉시 Mission FAIL을 의미하지는 않는다.

예:
- 추가 Code Review
- 관련 Open Source 코드 읽기
- Architecture 설명 훈련
- 관련 Study

## OPTIONAL

좋은 기회이지만 현재 목표와 시간 예산에 따라 선택한다.

예:
- 관련 세미나
- 선택 Hackathon
- 관심 기술 비교 실습
- 탐색 목적의 외부 프로그램

## 규칙

중요도는 성장 단계와 독립적이다.

가능한 조합 예:
- CORE + REQUIRED
- CORE + RECOMMENDED
- EXPLORE + OPTIONAL
- ADVANCED + RECOMMENDED
- PRO + OPTIONAL

전문 분야를 선택하면 기존 OPTIONAL이 RECOMMENDED 또는 REQUIRED로 승격될 수 있다.

## 판단 질문

새 활동을 등록할 때 다음을 확인한다.

1. 현재 Mission/Project 완료를 직접 앞당기는가?
2. 장기 Skill Gap을 메우는가?
3. 재사용 가능한 Evidence를 만드는가?
4. Project Lineage에 연결되는가?
5. 시간 대비 가치가 충분한가?

현재 Mission PASS를 지연시키는 비필수 고도화는 ADVANCED Backlog 또는 OPTIONAL로 이동한다.

# B1-2 Level 4 — Troubleshooting Unit Index

**목적:** OOM / CPU / Deadlock 장애를 `증상 → 관찰 → 실패 층 → 가설 → 최소 수정 → 재검증 → Evidence` 순서로 진단한다.  
**Gate:** TROUBLESHOOTING  
**Visual Learning:** DEFERRED

> 원칙: 먼저 관찰하고 나중에 수정한다. 실제 Runtime Evidence가 없는 상태를 PASS로 과장하지 않는다.

## 공통 진단 알고리즘

```text
Symptom
→ Observe
→ Layer
→ Hypothesis
→ Smallest Fix
→ Reverify
→ Recovery
→ Evidence
```

## 금지 습관

- 장애가 보이자마자 재부팅하거나 강제 종료
- PID를 확인하지 않고 시스템 전체 수치만 보고 원인 단정
- 여러 환경 변수를 한 번에 변경
- Mission 예시 출력을 실제 Evidence처럼 복사
- 실제 build에 없는 로그 문자열을 만들어 넣기

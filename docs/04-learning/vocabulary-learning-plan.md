# Codyssey Basic 미션 용어 학습 체계 기획

## 1. 목적

이 문서는 Codyssey Basic의 B1-1부터 B7-2까지 15개 수행 단위에서 필요한 용어를 체계적으로 추출하고, 입문자가 미션 수행 전에 무엇을 먼저 이해해야 하는지 판단하기 위한 공통 기준을 정의한다.

목표는 단순한 사전식 용어집이 아니다.

> 용어 인지 → 개념 이해 → 실제 적용 → 오류 진단 → 자기 설명 → 다음 미션으로 연결

각 미션은 선행지식, 핵심 개념, 구현, 구조·원리, 검증·트러블슈팅, 평가 설명, 복습, 심화의 흐름으로 확장한다.

## 3. Source of Truth

용어와 학습 자료는 일반 컴퓨터 지식을 임의로 확장하여 필수 요구사항처럼 만들지 않는다. 우선순위는 다음과 같다.

1. 원본 Mission PDF
2. 원본 Mission Markdown
3. 공식 Evaluation / 평가문항
4. 공식 운영 자료 중 해당 미션에 직접 관련된 내용
5. 실제 구현에 필수인 코드·설정·명령·파일 구조
6. 테스트와 검증에 필요한 항목
7. 오류 분석 및 트러블슈팅에 필요한 항목
8. 평가에서 자기 말로 설명해야 하는 항목

현재 미션 통과와 직접 관계없는 심화 이론은 기본 학습 흐름에 과도하게 넣지 않고 `Advanced`로 분리한다.

## 4. 용어 표기 표준

### 4.1 기본 표기

- `한글 용어 (English Term)`
- 약어가 있으면 `한글 용어 (English Term, ABBR)`

### 4.2 고유 기술명

Git, FastAPI, React, SQLAlchemy, GitHub Flow처럼 현업에서 영문 고유명사를 그대로 사용하는 기술은 억지로 번역하지 않는다.

### 4.3 약어

가능하면 다음 세 요소를 함께 관리한다.

- 한글 명칭
- 영문 원문
- 약어

## 5. 미션별 Level 구조

### Level 0 — 선수 용어
미션 설명을 읽고 시작하기 전에 필요한 기초 용어.

### Level 1 — 핵심 개념 용어
미션의 본질을 이해하기 위해 반드시 알아야 하는 핵심 용어. `Top Core`는 이 단계의 최소 핵심 집합으로 관리한다.

### Level 2 — 구현 필수 용어
실제 코드, 명령, 설정, 파일, 디렉터리, 도구를 사용하면서 필요한 용어.

### Level 3 — 구조·동작 원리 용어
기능이 왜 그렇게 동작하고 구조가 왜 그렇게 나뉘는지 설명하기 위한 용어.

### Level 4 — 검증·트러블슈팅 용어
실행 결과 확인, 로그 분석, 장애 원인 진단, 복구와 재검증에 필요한 용어.

### Level 5 — 평가·설명 필수 용어
평가에서 자기 말로 정의하고 구조·선택 이유·검증 근거까지 설명해야 하는 용어.

### Review
Level 0~5를 통합하여 복습 카드, 구두 퀴즈, V1~V5 Gate로 최종 점검하는 단계.

### Advanced
현재 미션 통과에는 필수적이지 않지만 심화 학습이나 실무 확장에 유용한 용어·기술.

---

## 6. 중요도 분류

Level과 중요도는 별도로 관리한다.

### CORE
미션의 본질을 이해하는 데 반드시 필요한 용어.

### REQUIRED
실제 수행을 위해 알아야 하는 용어.

### REFERENCE
필요할 때 찾아보면 되는 보조 용어.

> **Top Core = 해당 미션을 시작하기 전에 반드시 이해해야 하는 최소 핵심 용어 집합**

입문자가 전체 용어를 미션 시작 전에 암기하도록 하지 않는다.

---

## 7. 이해 수준 기준

| 수준 | 기준 |
|---|---|
| K1 — 인지 | 용어를 보고 무엇인지 알아볼 수 있다. |
| K2 — 이해 | 의미를 짧게 자기 말로 설명할 수 있다. |
| K3 — 적용 | 실제 미션의 코드·명령·설정에서 사용할 수 있다. |
| K4 — 설명 | 원리, 사용 이유, 구조적 관계까지 설명할 수 있다. |

- CORE: 주로 K3~K4
- REQUIRED: 주로 K2~K3
- REFERENCE: 주로 K1~K2

모든 용어를 K4까지 학습하지 않는다.

## 9. 학습 시점 — 20 : 60 : 20

### 미션 전 20%

- 최소 선수지식
- Top Core
- 미션의 핵심 원리를 이해하기 위한 용어

### 미션 수행 중 60%

- 실제 코드
- 명령
- 설정
- 파일 구조
- 실행 과정에서 만나는 용어
- 검증과 오류 해결

### 미션 완료 후 20%

- 구조적 원리
- 평가 설명
- 통합 복습
- 심화 및 다음 미션 연결

목표는 선행 암기가 아니라 **필요한 순간에 필요한 깊이까지 학습**하는 것이다.

## 10. 중복 용어의 누적 학습 상태

| 상태 | 의미 |
|---|---|
| NEW | 해당 용어의 최초 등장 |
| REVIEW | 이전 미션에서 배운 내용을 복습 |
| APPLY | 현재 미션에서 실제 적용 |
| DEEPEN | 더 깊은 원리 또는 사용법으로 확장 |
| INTEGRATE | 여러 기술과 결합하여 통합적으로 사용 |

각 용어의 최초 등장 미션과 재등장 미션을 추적하여 B1-1~B7-2 전체를 하나의 누적 학습 경로로 관리한다.

## 11. 선수관계와 Dependency Map

가나다순 용어집만 만들지 않는다.

```text
용어 A
  ↓
용어 B
  ↓
용어 C
  ↓
실제 미션 기능
```

여러 용어가 하나의 개념으로 합쳐지는 경우:

```text
A ─┐
B ─┼─→ D
C ─┘
```

장기적으로 이를 `Codyssey Basic Vocabulary Dependency Map` 또는 Knowledge Graph로 확장한다.

## 12. 미션별 최초 용어 출력 템플릿

미션별 최초 추출 단계에서는 설명을 붙이지 않고 용어명만 제시한다.

```text
# B?-? 미션 용어 지도

## Level 0 — 선수 용어
- 한글명 (English Term)

## Level 1 — 핵심 용어
- 한글명 (English Term, ABBR)

## Level 2 — 구현 필수 용어
- ...

## Level 3 — 구조·동작 원리 용어
- ...

## Level 4 — 검증·트러블슈팅 용어
- ...

## Level 5 — 평가·설명 필수 용어
- ...

## Advanced
- ...

## Top Core
- ...
```

첫 목록에서는 뜻, 비유, 예제, 만화, 실습 설명을 넣지 않는다.

## 12.1 디렉터리와 파일명 표준

학습 확장 단계에서는 **Mission Directory + Level File** 구조를 사용한다.

### 디렉터리

```text
{mission-number}-{english-mission-slug}/
```

예:

```text
b1-1-system-monitoring-automation/
b1-2-linux-troubleshooting/
b2-1-budget-tracker/
b2-2-git-team-collaboration/
```

영어 slug는 공식 제목을 문장 그대로 직역하기보다 **미션의 핵심 기능을 나타내는 짧고 안정적인 영문명**을 사용한다.

### 파일

```text
{mission-number}-00-index.md
{mission-number}-10-level-0-prerequisite.md
{mission-number}-20-level-1-core.md
{mission-number}-30-level-2-execution.md
{mission-number}-40-level-3-principles.md
{mission-number}-50-level-4-troubleshooting.md
{mission-number}-60-level-5-evaluation.md
{mission-number}-70-review-pack.md
{mission-number}-90-advanced.md
```

### 번호 의미

| 번호 | 역할 |
|---:|---|
| 00 | 미션 전체 지도·Source of Truth·학습 순서 |
| 10 | Level 0 선수지식 |
| 20 | Level 1 핵심 개념·Top Core |
| 30 | Level 2 실제 구현·실행 |
| 40 | Level 3 구조·동작 원리 |
| 50 | Level 4 검증·트러블슈팅 |
| 60 | Level 5 평가·자기 설명 |
| 70 | 통합 복습·Vocabulary Gate |
| 80 | 향후 실전 모의평가·추가 Lab 예약 |
| 90 | Advanced 선택 심화 |

### 네이밍 원칙

1. **디렉터리와 파일명은 영어**를 사용한다.
2. 파일명 맨 앞에는 **항상 해당 미션 번호**를 붙인다.
3. 두 자리 순서 번호를 사용해 GitHub·Linux·WSL·macOS의 정렬 순서와 학습 순서를 일치시킨다.
4. 문서 H1과 학습 설명은 한국어 중심으로 작성하고 핵심 전문 용어는 영어 원문을 병기한다.
5. 파일 내부에는 `이전 → Index → 다음` 링크를 두어 학습 순서를 잃지 않게 한다.
6. 미션별 `00-index`가 해당 미션의 학습 홈 페이지 역할을 한다.
7. 기존 평면 파일을 구조화 디렉터리로 전환할 때는 **내부 링크를 전수 갱신하고 깨진 링크를 검증한 뒤** 기존 파일을 제거한다.

B1-1을 첫 기준 구현으로 사용하고 B1-2~B7-2에 순차 적용한다.

## 15. 용어 선정 STOP RULE

### 포함 기준

다음 중 하나 이상에 해당하면 포함한다.

- Mission PDF 또는 Evaluation에 직접 등장
- 미션의 핵심 개념 이해에 필수
- 실제 코드·명령·설정·파일 구조에서 사용
- 테스트·검증에 필요
- 오류 원인 분석에 필요
- 평가에서 설명해야 함
- 후행 필수 개념의 직접적인 선수지식

### 기본 제외 기준

- 미션과 직접 관계없는 주변 기술
- 과도한 내부 구현 이론
- 현재 단계에서 사용하지 않는 엔터프라이즈 기술
- 평가 및 실제 구현에 필요하지 않은 파생 용어
- 학습을 지연시키는 과도한 심화 지식

판정 질문:

> 이 용어를 모르면 현재 미션의 이해·수행·검증·평가 중 하나가 실제로 어려워지는가?

YES이면 포함하고, NO이면 기본 목록에서 제외하거나 Advanced로 이동한다.

## 16. Vocabulary Gate

### V1 — 인지
핵심 용어를 보고 무엇인지 알아볼 수 있다.

### V2 — 이해
Top Core의 의미를 간단한 자기 말로 설명할 수 있다.

### V3 — 관계
핵심 용어 사이의 선후관계와 연결 구조를 이해한다.

### V4 — 적용
실제 미션의 코드·명령·설정에서 해당 용어가 어디에 사용되는지 찾고 적용할 수 있다.

### V5 — 설명
평가 대상 핵심 용어에 대해 원리·선택 이유·검증 근거를 자기 말로 설명할 수 있다.

모든 용어가 V5에 도달할 필요는 없다. Top Core 및 평가 핵심 용어를 중심으로 V4~V5를 목표로 한다.

## 17. 전체 산출물

### 17.1 Mission Vocabulary
B1-1~B7-2 각각의 미션별 용어 지도와 Level별 학습 파일.

### 17.2 Basic Master Vocabulary
15개 미션 전체의 중복을 제거하고 최초 등장과 재사용 위치를 연결한 통합 용어집.

### 17.3 Dependency Map
선수 용어와 후행 개념의 연결 관계를 나타내는 지식 지도.

### 17.4 Learning Path
입문자가 실제로 공부할 순서를 나타내는 학습 경로.

## 18. 진행 순서

```text
Mission Vocabulary 추출
  ↓
Level 0~5 + Advanced 분류
  ↓
Top Core
  ↓
품질 감사
  ↓
00~90 Level별 학습 파일 확장
  ↓
V1~V5 Review
  ↓
다음 미션
```

B1-1에서 디렉터리·파일 구조까지 기준 구현을 검증하고 B1-2~B7-2에 같은 방식으로 적용한다.

## 19. 핵심 원칙 요약

1. 한글과 영어를 함께 표기한다.
2. 약어는 영문 원문과 함께 관리한다.
3. 고유 기술명은 억지로 번역하지 않는다.
4. 미션별 Level 0~5와 Advanced를 사용한다.
5. 중요도는 CORE / REQUIRED / REFERENCE로 별도 관리한다.
6. 각 미션마다 Top Core를 선정한다.
7. 필요한 이해 수준은 K1~K4로 구분한다.
8. 미션 전·중·후 학습량은 20:60:20을 기본으로 한다.
9. 반복 용어는 NEW → REVIEW → APPLY → DEEPEN → INTEGRATE로 관리한다.
10. 선수관계를 기록하여 Dependency Map을 만든다.
11. 첫 용어 목록에는 설명을 넣지 않는다.
12. 용어 확정 후 설명·비유·도식·실습·오류 해결·평가 설명으로 확장한다.
13. 현재 미션 통과에 필요하지 않은 심화 용어는 Advanced로 분리한다.
14. Source of Truth를 우선하고 일반 지식을 필수 요구사항처럼 임의 추가하지 않는다.
15. 디렉터리는 `미션 번호 + 영어 slug`, 파일은 `미션 번호 + 순서 번호 + Level/목적`으로 통일한다.
16. 파일 구조와 학습 선후관계를 동일하게 만든다.
17. 구조 변경 시 관련 링크를 전수 갱신하고 깨진 링크를 검증한다.
18. 목표는 암기가 아니라 `이해 → 적용 → 진단 → 설명`이다.

# Codyssey Basic 미션 용어 학습 체계 기획

## 1. 목적

이 문서는 Codyssey Basic의 B1-1부터 B7-2까지 15개 수행 단위에서 필요한 용어를 체계적으로 추출하고, 입문자가 미션 수행 전에 무엇을 먼저 이해해야 하는지 판단하기 위한 공통 기준을 정의한다.

목표는 단순한 사전식 용어집을 만드는 것이 아니다. 각 미션에서 필요한 용어를 선행지식, 핵심 개념, 구현, 구조와 원리, 검증과 트러블슈팅, 평가 설명의 순서로 배치하여 다음 학습 흐름을 만든다.

> 용어 인지 → 개념 이해 → 실제 적용 → 오류 진단 → 자기 설명 → 다음 미션으로 연결

현재 단계에서는 **용어 체계와 작성 규칙만 확정**한다. 실제 B1-1~B7-2 용어 목록은 이후 미션별로 순차 작성한다.

## 3. Source of Truth

용어는 일반 컴퓨터 지식을 임의로 확장해서 수집하지 않는다. 다음 순서를 기준으로 추출한다.

1. 원본 Mission PDF
2. 원본 Mission Markdown
3. 공식 Evaluation / 평가문항
4. 공식 운영 자료 중 해당 미션에 직접 관련된 내용
5. 실제 미션 구현에 필수인 코드·설정·명령·파일 구조
6. 테스트와 검증에 필요한 항목
7. 오류 분석 및 트러블슈팅에 필요한 항목
8. 학습자가 평가에서 자기 말로 설명해야 하는 항목

현재 미션 통과와 직접 관련이 없는 심화 이론은 본 목록에 무리하게 포함하지 않고 `Advanced`로 분리한다.

---

## 4. 용어 표기 표준

### 4.1 기본 표기

모든 일반 용어는 다음 형식을 기본으로 한다.

- `한글 용어 (English Term)`
- 약어가 있으면 `한글 용어 (English Term, ABBR)`

### 4.2 고유 기술명

Git, FastAPI, React, SQLAlchemy, GitHub Flow처럼 현업에서 영문 고유명사를 그대로 사용하는 기술은 억지로 번역하지 않는다. 필요한 경우 분류만 한국어로 표시한다.

### 4.3 약어 원칙

약어는 가능한 경우 다음 3요소를 함께 관리한다.

- 한글 명칭
- 영문 원문
- 약어

예시 형식만 정의하며, 실제 용어는 미션별 문서에서 작성한다.

---

## 5. 미션별 7단계 용어 구조

각 미션의 용어는 아래 순서로 배치한다.

### Level 0 — 선수 용어

미션 설명을 읽고 시작하기 전에 필요한 기초 용어.

### Level 1 — 핵심 개념 용어

미션의 본질을 이해하기 위해 반드시 알아야 하는 핵심 용어.

### Level 2 — 구현 필수 용어

실제 코드, 명령, 설정, 파일, 디렉터리, 도구를 사용하면서 필요한 용어.

### Level 3 — 구조·동작 원리 용어

기능이 왜 그렇게 동작하는지, 구조가 왜 그렇게 나뉘는지 설명하기 위해 필요한 용어.

### Level 4 — 검증·트러블슈팅 용어

실행 결과 확인, 로그 분석, 장애 원인 진단, 복구와 재검증에 필요한 용어.

### Level 5 — 평가·설명 필수 용어

평가에서 학습자가 자기 말로 정의하고 구조 또는 선택 이유까지 설명해야 하는 용어.

### Advanced — 고도화 용어

현재 미션 통과에는 필수적이지 않지만 심화 학습이나 실무 확장에 유용한 용어.

---

## 6. 중요도 분류

Level과 중요도는 별도로 관리한다.

### CORE

미션의 본질을 이해하는 데 반드시 필요한 용어.

### REQUIRED

실제 수행을 위해 알아야 하는 용어.

### REFERENCE

필요할 때 찾아보면 되는 보조 용어.

각 미션에서는 전체 용어와 별도로 `Top Core`를 선정한다.

> **Top Core = 해당 미션을 시작하기 전에 반드시 이해해야 하는 최소 핵심 용어 집합**

입문자가 전체 용어를 미션 시작 전에 암기하도록 하지 않는다.

---

## 7. 이해 수준 기준

각 용어는 필요한 학습 깊이에 따라 다음 수준을 부여한다.

| 수준 | 기준 |
|---|---|
| K1 — 인지 | 용어를 보고 무엇인지 알아볼 수 있다. |
| K2 — 이해 | 의미를 짧게 자기 말로 설명할 수 있다. |
| K3 — 적용 | 실제 미션의 코드·명령·설정에서 사용할 수 있다. |
| K4 — 설명 | 원리, 사용 이유, 구조적 관계까지 설명할 수 있다. |

모든 용어를 K4까지 학습하지 않는다.

- CORE: 주로 K3~K4
- REQUIRED: 주로 K2~K3
- REFERENCE: 주로 K1~K2

---

## 8. 용어 종류 분류

필요한 경우 각 용어에 다음 Category를 부여한다.

- 개념 (Concept)
- 기술 (Technology)
- 도구 (Tool)
- 명령 (Command)
- 파일 (File)
- 디렉터리 (Directory)
- 설정 (Configuration)
- 프로토콜 (Protocol)
- 자료구조 (Data Structure)
- 알고리즘 (Algorithm)
- 패턴 (Pattern)
- 아키텍처 (Architecture)
- 보안 (Security)
- 오류·장애 (Error / Failure)
- 테스트·검증 (Test / Verification)
- 협업 (Collaboration)
- 배포·운영 (Deployment / Operations)
- 평가 (Evaluation)

개념명, 명령어, 기술명, 파일명을 같은 종류의 지식처럼 다루지 않기 위한 분류다.

---

## 9. 학습 시점: 20 : 60 : 20 원칙

모든 용어를 먼저 공부한 뒤 미션을 시작하는 방식은 사용하지 않는다.

### 미션 전 20%

- Top Core
- 최소 선수지식
- 미션의 핵심 원리를 이해하기 위한 용어

### 미션 수행 중 60%

- 실제 코드
- 명령
- 설정
- 파일 구조
- 실행 과정에서 만나는 용어

### 미션 완료 후 20%

- 구조적 원리
- 평가 설명
- 복습
- 심화 및 다음 미션 연결

목표는 `선행 암기`가 아니라 `필요한 순간에 필요한 깊이까지 학습`하는 것이다.

---

## 10. 중복 용어의 누적 학습 상태

같은 용어가 여러 미션에서 반복될 경우 매번 신규 용어처럼 다루지 않는다.

| 상태 | 의미 |
|---|---|
| NEW | 해당 용어의 최초 등장 |
| REVIEW | 이전 미션에서 배운 내용을 복습 |
| APPLY | 현재 미션에서 실제 적용 |
| DEEPEN | 더 깊은 원리 또는 사용법으로 확장 |
| INTEGRATE | 여러 기술과 결합하여 통합적으로 사용 |

각 용어의 `최초 등장 미션`과 `재등장 미션`을 추적하여 B1-1~B7-2 전체가 하나의 누적 학습 경로가 되도록 한다.

---

## 11. 선수관계와 Dependency Map

가나다순 용어집만 만들지 않는다.

각 용어 사이에 필요한 경우 선수관계를 기록한다.

```text
용어 A
  ↓
용어 B
  ↓
용어 C
  ↓
실제 미션 기능
```

여러 용어가 하나의 개념으로 합쳐지는 경우도 기록한다.

```text
A ─┐
B ─┼─→ D
C ─┘
```

장기적으로 이를 `Codyssey Basic Vocabulary Dependency Map` 또는 `Knowledge Graph`로 확장한다.

---

## 12. 미션별 실제 출력 템플릿

미션별 최초 출력에서는 **설명을 붙이지 않고 용어명만** 제시한다.

```text
# B?-? 미션 용어 지도

## Level 0 — 선수 용어
- 한글명 (English Term)

## Level 1 — 반드시 이해해야 하는 핵심 용어
- 한글명 (English Term, ABBR)

## Level 2 — 구현 필수 용어
- ...

## Level 3 — 구조·동작 원리 용어
- ...

## Level 4 — 검증·트러블슈팅 용어
- ...

## Level 5 — 평가에서 설명해야 하는 용어
- ...

## Advanced — 고도화 용어
- ...

## Top Core
- ...
```

첫 목록에서는 뜻, 비유, 예제, 만화, 실습 설명을 넣지 않는다.

---

## 13. 용어 목록 확정 후 학습 순서

용어 목록을 확정한 이후에는 다음 순서로 확장한다.

1. 전체 용어 지도 확인
2. Top Core 선정
3. 쉬운 한 줄 설명
4. 생활 속 비유
5. 그림·도식 또는 만화
6. 용어와 개념의 연결 관계
7. 초미니 실습
8. 실제 미션 수행
9. 의도적인 오류 발생 및 관찰
10. 오류 해결
11. 평가 예상 질문
12. 자기 말로 설명
13. 복습
14. 다음 미션과 연결

목표는 `용어를 봤다`에서 끝내지 않고 `이해 → 적용 → 진단 → 설명`으로 발전시키는 것이다.

## 14. 내부 관리 데이터 구조

향후 통합 용어 DB 또는 학습 대시보드로 확장할 수 있도록 다음 필드를 관리할 수 있다.

| 필드 | 의미 |
|---|---|
| Term ID | 용어 고유 ID |
| Mission ID | B1-1~B7-2 |
| Korean Term | 한글 용어 |
| English Term | 영문 원문 |
| Abbreviation | 약어 |
| Category | 용어 종류 |
| Level | Level 0~5 / Advanced |
| Priority | CORE / REQUIRED / REFERENCE |
| Knowledge Level | K1~K4 |
| First Seen | 최초 등장 미션 |
| Lifecycle | NEW / REVIEW / APPLY / DEEPEN / INTEGRATE |
| Prerequisite | 선수 용어 |
| Related Terms | 연관 용어 |
| Implementation | 구현 필요 여부 |
| Evaluation | 평가 설명 필요 여부 |
| Troubleshooting | 오류 해결 필요 여부 |
| Reuse | 후속 미션 재사용 여부 |
| Advanced | 고도화 분리 여부 |

사용자에게 모든 필드를 한 번에 보여주는 것이 목적은 아니다. 내부 관리에는 충분한 정보를 두고 학습 단계별로 필요한 정보만 노출한다.

## 15. 용어 선정 STOP RULE

관련 용어를 끝없이 추가하지 않는다.

### 포함 기준

다음 중 하나 이상에 해당하면 포함한다.

- Mission PDF 또는 Evaluation에 직접 등장
- 미션의 핵심 개념 이해에 필수
- 실제 코드에서 사용
- 실제 명령에서 사용
- 설정 또는 파일 구조에서 사용
- 테스트·검증에 필요
- 오류 원인 분석에 필요
- 평가에서 설명해야 함
- 후행 필수 개념의 직접적인 선수지식

### 기본 제외 기준

다음은 현재 미션의 본 목록에서 제외하고 필요한 경우 Advanced로 이동한다.

- 미션과 직접 관계없는 주변 기술
- 과도한 내부 구현 이론
- 현재 단계에서 사용하지 않는 엔터프라이즈 기술
- 평가 및 실제 구현에 필요하지 않은 파생 용어
- 학습을 지연시키는 과도한 심화 지식

판정 질문은 다음과 같다.

> 이 용어를 모르면 현재 미션의 이해·수행·검증·평가 중 하나가 실제로 어려워지는가?

YES이면 포함하고, NO이면 기본 목록에서 제외하거나 Advanced로 이동한다.

## 16. Vocabulary Gate

각 미션의 용어 학습은 다음 Gate로 확인한다.

### Gate V1 — 인지

핵심 용어를 보고 무엇인지 알아볼 수 있다.

### Gate V2 — 이해

Top Core의 의미를 간단한 자기 말로 설명할 수 있다.

### Gate V3 — 관계

핵심 용어 사이의 선후관계와 연결 구조를 이해한다.

### Gate V4 — 적용

실제 미션의 코드·명령·설정에서 해당 용어가 어디에 사용되는지 찾을 수 있다.

### Gate V5 — 설명

평가 대상 핵심 용어에 대해 원리와 선택 이유를 자기 말로 설명할 수 있다.

모든 용어가 Gate V5에 도달할 필요는 없다. Top Core 및 평가 핵심 용어를 중심으로 V4~V5를 목표로 한다.

---

## 17. 전체 산출물

15개 미션의 용어 작업이 완료되면 다음 4개의 학습 자산으로 통합한다.

### 17.1 Mission Vocabulary

B1-1~B7-2 각각의 미션별 용어 지도.

### 17.2 Basic Master Vocabulary

15개 미션 전체의 중복을 제거하고 최초 등장과 재사용 위치를 연결한 통합 용어집.

### 17.3 Dependency Map

선수 용어와 후행 개념의 연결 관계를 나타내는 지식 지도.

### 17.4 Learning Path

입문자가 실제로 공부할 순서를 나타내는 학습 경로.

---

## 18. 진행 순서

다음 방식으로 한 미션씩 진행한다.

```text
B1-1 용어 전체 추출
  ↓
설명 없는 단계별 목록 작성
  ↓
Top Core 선정
  ↓
누락·과잉 검토
  ↓
표준 확정
  ↓
B1-2
  ↓
...
  ↓
B7-2
```

첫 적용 대상은 B1-1이다. B1-1에서 분류 체계를 실제로 검증한 뒤 같은 방식으로 나머지 14개 미션에 적용한다.

## 19. 핵심 원칙 요약

1. 한글과 영어를 함께 표기한다.
2. 약어는 영문 원문과 함께 관리한다.
3. 고유 기술명은 억지로 번역하지 않는다.
4. 미션별 Level 0~5와 Advanced를 사용한다.
5. 중요도는 CORE / REQUIRED / REFERENCE로 별도 관리한다.
6. 각 미션마다 Top Core를 선정한다.
7. 필요한 이해 수준은 K1~K4로 구분한다.
8. 미션 전·중·후 학습량은 20:60:20을 기본으로 한다.
9. 반복 용어는 NEW → REVIEW → APPLY → DEEPEN → INTEGRATE로 관리한다.
10. 선수관계를 기록하여 Dependency Map을 만든다.
11. 첫 용어 목록에는 설명을 넣지 않는다.
12. 용어 확정 후 설명·비유·도식·실습·오류 해결·평가 설명으로 확장한다.
13. 현재 미션 통과에 필요하지 않은 심화 용어는 Advanced로 분리한다.
14. Source of Truth를 우선하고 일반 지식을 필수 요구사항처럼 임의 추가하지 않는다.

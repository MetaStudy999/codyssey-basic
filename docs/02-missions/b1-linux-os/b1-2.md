# B1-2 — Linux Troubleshooting

## Mission Identity

- 제목: 컴퓨터가 갑자기 느려지거나 멈췄을 때 원인 찾아 고치기
- 영역: Linux & OS
- 공식 구분: 필수
- Repository: https://github.com/MetaStudy999/codyssey-basic-b1-2-linux-troubleshooting
- Growth Stage: `CORE`

실제 수행 상태와 G1~G8은 `config/missions.yaml`을 Source of Truth로 사용한다.

## Core Goal

Memory/OOM, CPU 과부하, Deadlock과 같은 운영 문제를 **재현 → 관찰 → 분석 → 복구 → 보고**하는 능력을 훈련한다.

## Core Terms

- Process / Thread
- Memory
- Memory Leak
- OOM / OOM Killer
- CPU Usage / Load
- Latency
- Lock / Mutex
- Deadlock
- Log
- Monitoring
- Root Cause
- Before / After Evidence

```text
Symptom
   ↓

   ↓

```

## Core Scenario Summary

기존 Control Tower의 B1-2 요약은 다음 세 축을 중심으로 한다.

- Memory Leak / OOM
- CPU Spike / Latency
- Deadlock

각 문제를 단순히 고치는 데서 끝내지 않고, 관측 정보와 로그를 바탕으로 원인과 조치 근거를 설명한다.

공식 세부 요구는 Mission Source와 개별 Repository의 Work Packet을 기준으로 다시 확인한다.

## Evidence Standard

좋은 Troubleshooting Evidence는 최소한 다음을 연결한다.

```text
문제 발생 전/초기 상태
+ 증상
+ 관측 명령/로그
+ 가설
+ 원인 판단 근거
+ 수정
+ 동일 조건 재검증
+ Before/After
```

## Learning

B1-2의 기존 학습 자산은 `docs/04-learning/vocabulary/b1-2-linux-process-resource-troubleshooting/`에 연결되어 있다.

CORE 학습 목표는 명령어 암기보다 다음 질문에 답하는 것이다.

1. 무엇이 이상한가?
2. 어느 Layer를 먼저 확인하는가?
3. 어떤 증거가 가설을 지지/반박하는가?
4. 가장 작은 수정은 무엇인가?
5. 정상 복귀를 어떻게 증명하는가?

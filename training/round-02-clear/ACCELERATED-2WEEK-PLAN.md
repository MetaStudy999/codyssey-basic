> **기준 레포(Canonical Control Repository):** `MetaStudy999/codyssey-basic`
>
> 적용 범위: B1-1 ~ B7-2 전체 15개 Mission/Project
>
> 이 문서의 시간은 **공식 학습시간을 대체하지 않는 내부 실행 목표(Target Budget)** 이다. 공식 학습시간·요구사항·평가기준은 제2기 Mission PDF가 우선한다.

## 1. 목표

Round 02에서는 기존 `training/round-01-clear/`의 구현·가이드·평가자료를 기준 구현(Reference)으로 적극 활용하고, 다음에 시간을 집중한다.

```text
제2기 PDF와 차이 확인
→ 평가항목 먼저
→ 최소 통과 경로
→ 필요한 부분만 수정
→ 실제 Runtime
→ Verification
→ Evidence
→ 평가 설명
→ 모의평가
```

### 시간 목표

- **필수 11개:** 약 **100시간** 초압축 목표
- **선택 4개:** 약 **50시간** 추가 목표
- **전체 15개:** 약 **150시간** 내부 목표
- 14일 전체 15개 수행 시 평균 약 **10.7시간/일**
- 14일 필수 11개 우선 시 평균 약 **7.1시간/일**

실제 시간은 오류, 팀원 일정, PR 리뷰, 클라우드 배포, 외부 서비스 대기 등에 따라 늘어날 수 있다.

## 4. 시간을 줄이는 방법

줄여도 되는 것:
- 이미 이해한 기본 개념의 반복 설명
- Round 01과 동일한 코드의 재작성
- UI 고도화
- 보너스 기능
- 비필수 리팩터링
- 현재 평가와 무관한 확장
- 공식 요구가 없는 교차 플랫폼 중복 수행
- 장식성 문서 작업

줄이면 안 되는 것:
- 제2기 공식 요구사항 확인
- 실제 Runtime
- 필수 기능 검증
- Verification
- 현재 Round Evidence
- Secret 점검
- 평가 WHY 설명
- 공식 팀 협업 요구가 있는 경우의 실제 협업 기록

## 5. 미션별 시간 사용 원칙

각 미션의 초압축 시간은 다음 비율을 기본으로 한다.

```text
10%  공식 PDF + 기존 Evaluation 확인
10%  Round 01 차이 분석 + 최소 통과 경로
55%  구현/수정 + 실제 실행
15%  Verification + Evidence
10%  평가 설명 + 모의평가
```

미션이 예상보다 빨리 끝나면 남는 시간을 다음 미션으로 이동한다. 예상보다 오래 걸리면 보너스·고도화를 중단하고 공식 필수 요구와 평가 항목만 남긴다.

## 6. 첫 미션에서 속도 보정

B1-1은 전체 계획의 기준 측정 미션으로 사용한다.

```text
B1-1 목표 9h
→ 실제 소요시간 기록
→ 목표 대비 배율 계산
→ B2-1 이후 시간 예산 재보정
```

예:
- B1-1 실제 6h → 이후 미션 예산을 공격적으로 축소 가능
- B1-1 실제 12h → 이후 일정에 약 1.33배 보정 검토

시간 때문에 Runtime/Verification/Evidence를 삭제하지 않는다.

## 7. 완료 기준

초압축 모드에서도 CLEAR 기준은 동일하다.

```text
공식 요구사항
+ 실제 구현
+ 실제 Runtime
+ Verification PASS
+ 필요한 Evidence
+ 평가 설명 가능
+ Secret 노출 없음
```

> **초압축은 요구사항을 줄이는 방식이 아니라, 중복 작업을 줄이고 기존 자산을 재사용하는 방식이다.**
